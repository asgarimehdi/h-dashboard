## Direction Findings

### D1: Flutter API parity gap

- **Evidence**: `routes/api.php` has only 4 controllers (Unit read, Todo CRUD, Zabbix traffic, Zabbix multi-latest). `routes/web.php` has ticket workflow (create/inbox/monitoring), hardware CRUD, person/kargozini management, 5 report types, 7 map views, user/role/permission management — none exposed via API.
- **Impact**: Flutter mobile app can only authenticate, list units, manage todos, and query Zabbix. Core features (tickets, hardware inventory, personnel, maps) are inaccessible from mobile. Plans 012 (Ticket API), 014 (Unit write API), 015 (Reports API) exist but are unexecuted.
- **Effort**: L (multi-sprint — each API controller is a separate effort)
- **Risk**: MED — API design decisions affect all future mobile clients
- **Confidence**: HIGH — clear evidence in routes, controllers, and existing plans
- **Fix sketch**: Execute Plan 012 (Ticket API) first as highest-value unblocker, then Plan 014 (Unit write), then expand to Hardware/Person APIs.

### D2: Missing intent documentation

- **Evidence**: Zero ADRs, no PRD.md, no PRODUCT.md, no CONTEXT.md, no DESIGN.md. Plan 011 specifies creating these but is unexecuted. `README.md` is 78 lines of basic setup in Persian.
- **Impact**: New contributors and AI agents cannot reconstruct why architectural decisions were made. Plans reference "the pattern discussed above" which doesn't exist. Repeated re-discovery of settled tradeoffs.
- **Effort**: M (1-2 days to draft initial docs from codebase analysis)
- **Risk**: LOW — additive, no code changes
- **Confidence**: HIGH — confirmed by file search
- **Fix sketch**: Execute Plan 011 to create ADRs for key decisions (Livewire Volt over separate classes, recursive CTE for unit hierarchy, Spatie permissions model, PostGIS boundary approach), plus a minimal PRODUCT.md describing the target user and core workflows.

### D3: Orphaned maps/units component

- **Evidence**: `resources/views/livewire/maps/units.blade.php` (135 lines, functional) exists but has NO matching route in `routes/web.php`. AGENTS.md line 147 documents `/maps/units` as a valid route — documentation/code mismatch. The `interactive` map serves a similar purpose and has a route.
- **Impact**: Dead code. AGENTS.md is wrong about this route. Confusing for anyone navigating the codebase.
- **Effort**: S (either add the route or delete the file + update AGENTS.md)
- **Risk**: LOW — either path is clean
- **Confidence**: HIGH — confirmed by grep of routes/web.php
- **Fix sketch**: Delete `maps/units.blade.php` (the interactive map covers the same use case) and remove the entry from AGENTS.md. Or add the route if it should exist.

### D4: Dashboard `deadline` field mismatch

- **Evidence**: `resources/views/livewire/dashboard.blade.php:88` queries `->where('deadline', '<', now())` for overdue tickets. `app/Models/Ticket.php` fillable does NOT include `deadline`. The field may exist in the migration but is not declared in the model.
- **Impact**: Dashboard may silently skip overdue ticket queries or show incorrect data.
- **Effort**: S (verify migration, add to fillable if column exists, or fix the query)
- **Risk**: LOW — isolated to dashboard view
- **Confidence**: MED — need to verify migration schema
- **Fix sketch**: Check `tickets` table schema for `deadline` column. If it exists, add to Ticket model fillable. If not, remove the query from dashboard or add the column via migration.

### D5: Duplicate API endpoints

- **Evidence**: `routes/api.php:31-38` defines both `GET /api/user` and `GET /api/me` — both return `$request->user()` with identical logic.
- **Impact**: Confusion for API consumers. Two endpoints to maintain for the same data. Singular/plural inconsistency (`/api/unit` vs `/api/todos`).
- **Effort**: S (remove one endpoint, deprecate with redirect)
- **Risk**: LOW — if Flutter app uses one, redirect the other
- **Confidence**: HIGH — confirmed in routes/api.php
- **Fix sketch**: Keep `/api/user` (matches Laravel convention), remove `/api/me` or redirect it. Also consider renaming `/api/unit` to `/api/units` for consistency.
